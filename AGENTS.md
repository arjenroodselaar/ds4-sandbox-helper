## Style

Comments are for what the code cannot show. A comment that restates a name, a type or
the line below it gets deleted, not shortened.

Close sentences. Do not chain clauses with `:` or `;`. Use a comma, a connecting `and`,
or start a new sentence. Those two characters are for enumerations.

Keep it short. No teaching asides, no narration of how the code works, no "as the X
does" padding. The reason a thing is done this way is worth a line; the consequence of
not doing it is usually the line worth having.

The same holds for text a model or a person reads: `--help`, error messages and tool
output are written short and simple.
